# B Stage112 채택 및 운영 전환 — 2026-09-10

사용자가 B플랜을 `b_regime_guard_stage112`로 업데이트하도록 승인했다. A플랜 `answer_mdd30`은 변경하지 않으며 사용자가 켜 둔 B의 `enabled=true`, `test_mode=false`도 유지한다.

## 2026-09-10 시간 경계 오류 복구

- Stage112 전환 때 DB 원자 함수 3개(`plan_b_publish_opportunities`, `plan_b_reserve_intents`, `plan_b_claim_intent`)에 남은 Stage93 버전/전략/주문 접두어 검사를 Stage112로 동기화했다.
- `plan_b_execution_intents_client_order_id_check`에 `pb112-`를 허용했다.
- 같은 시간의 `up_to_date` 점검만으로는 발견되지 않고 다음 정각 발행에서 `opportunity bootstrap required`가 발생하던 결함이다.
- 소유자가 켜 둔 `enabled=true`, `test_mode=false`는 변경하지 않았다.

## 2026-09-10 Edge 동시호출 완화

- 매분 같은 초에 몰리던 B 신호/진입/청산/Telegram/HTTP 오류수집 작업을 한 분 안에서 분산했다.
- 순서는 B 신호 정각, 청산 5초, 진입 15초, Telegram 35초, HTTP 결과수집 50초다.
- 단발성 `plan-b-http` 장애는 B의 신호·진입·청산 세 상태가 오류 이후 모두 정상 갱신되면 복구로 처리하며, 무관한 뉴스/수집기 heartbeat 때문에 거짓 오류 알림으로 승격하지 않는다.
- 매매 허용 상태와 전략 조건, 5분 진입 TTL은 변경하지 않았다.

## 변경 범위

- 신규진입 후 총 명목노출은 실제 BingX Equity의 3.75배 이하가 되도록 동시 주문을 비례 감액한다.
- 실제 Equity의 영속 고점 대비 낙폭이 25%에 도달하면 168시간 동안 신규진입만 중지한다. 중지 중에도 기존 포지션 조회·수익보호·시간청산·체결정산은 계속한다. 중지 종료 시 당시 Equity로 고점을 다시 시작한다.
