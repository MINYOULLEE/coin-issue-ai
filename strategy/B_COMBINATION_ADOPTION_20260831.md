# B 새 조합 채택 및 전환 기록

사용자 승인: “이거 채택 B 업데이트 이걸로 해주고 정확하게 연구들 결과까지 다 저장해놔. B는 모든 것들을 이 조합으로 업데이트한다.”

## 정본과 상태

- 목표: `plan_b_combination_standard.json`, `b_core_sparse_stage26_v1`.
- 기존 운영: `plan_b_standard.json`, `b_reserved_margin_stage16_v1`. 원본은 `archive/plan_b_stage16_v1.json`.
- A 매매 방식, 계정, 담보, 운영 스위치 변경 없음.
- 운영 B 조회: enabled=true, test_mode=false, 실거래 시작 기준 $150, DB 열린 거래 0건, 미결 예약 0건. 거래소 체결 보증으로 해석하지 않는다.
- **전환 미완료**: 이번 준비 모듈은 운영 진입점에서 import하지 않는다. 현 운영 B를 끄거나 새 조합으로 배포했다고 표시하지 않는다.

## 채택한 방법

Stage16의 AVAX/ICP/BCH/DOGE/UNI를 그대로 기본 구성으로 유지한다. 기본 기회가 없는 시간에 ALGO 급락/급등 꼬리 반전, ETH/VET 이전 24시간 고저점 돌파 실패 반전을 배치한다. 1시간 완료봉만 사용한다. 보조 레버리지 3배, 보유 1시간, 각 신호 희망 담보 90%. 5% 여유와 비용을 제외한 동일 B 계좌의 가용 담보 안에서 동시 요청을 비례 감액한다.

보조 청산 체결·잔량 0·종료 확인 전에는 기본 구성 진입을 대기한다. 원 신호 확정 후 5분 미만, 방향상 불리한 이동 0.35% 이내일 때만 진입하며 종료 예정시각은 연장하지 않는다. 정해진 시간에 청산하며 고정 가격 손절/익절은 추가하지 않았다.

### 운영 이식 시 발견한 누락 위험

1. 기존 실행부는 현재 보유/예약을 확인하지만 연구의 **선택 기회 재진입 제한**을 별도로 저장하지 않는다. 연구는 주문을 거절해도 선택 기회의 제한을 유지한다.
2. 보조는 1시간 보유지만 연구 `opportunities()`의 `nxt=i+hold+1` 때문에 선택 신호 사이에 최소 2시간이 필요하다. 1시간마다 재진입하면 다른 전략이다.
3. 기본 5종목 모두의 같은 시간 신호를 검증한 뒤에만 '기본 기회 없음'을 확정해야 한다. 조회 실패를 신호 없음으로 대체하면 안 된다.
4. 여러 워커에서 검사 후 주문 사이에 경쟁이 생기므로 순수 함수 검사만으로 부족하다. DB에서 기회 상태/신호 발행/그룹별 담보 예약을 원자적으로 처리해야 한다.

## 준비 코드와 남은 전환 작업

준비 코드: `supabase/functions/_shared/plan_b_combination.mjs`. 보조 신호, 기본 기회 우선, 보유와 별개인 선택 제한, 청산 확인 대기, 5분 만료, 불리한 가격 재검사, 동일 계좌 비례 담보 배분. 순수 모듈이며 주문·DB 변경 없음.

남은 작업:

- 연구와 일치하는 기본/보조 기회 상태 초기화 및 지속 저장, 누락 시간 복구.
- DB 트랜잭션으로 전체 시간 신호 발행과 기본/보조 상호 배제를 보장하고 실제 동시 워커 테스트.
- 부분 체결/통신 불명/청산 확인 지연 상태를 기존 장부·실행부와 통합.
- B 계정 ALGO/ETH/VET 계약 최소수량·격리·양방향 3배 확인.
- 실행기·신호기·계좌 조회·UI·텔레그램의 동일 버전 전환, 운영 소스 대조. 표시만 먼저 '운영 완료'로 바꾸지 않는다.

완료하지 않은 위 항목을 지우거나 실거래 검증 완료로 바꾸지 않는다. 사용자 실거래 스위치는 그대로 유지한다.
