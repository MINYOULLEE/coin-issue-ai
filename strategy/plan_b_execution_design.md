# B플랜 즉시 진입 보조 기준

## 목적

기본 신호를 바꾸지 않고 신호 확정과 주문 체결 사이의 운영 지연만 통제한다.
5분봉 검증에서 5분 진입 성과가 가장 좋았다는 이유로 일부러 기다리지 않는다.

## 실행 순서

1. 완료된 신호봉으로 B플랜 신호를 확정한다.
2. 신호 ID를 원자적으로 선점해 중복 실행을 막는다.
3. 1초 이내 B플랜 주문 함수로 전송한다.
4. 주문 전 현재가가 신호가보다 불리하게 0.35% 넘게 움직였으면 추격하지 않는다.
5. 신호 ID 기반 고정 clientOrderId로 시장가 주문을 한 번 제출한다.
6. 응답이 불명확하면 재주문 전에 같은 clientOrderId를 거래소에서 먼저 조회한다.
7. 250ms, 750ms, 1.5초 간격으로 최대 3회까지만 통신 복구를 시도한다.
8. 접수 후 500ms 간격으로 최대 10초 동안 실제 체결가와 수량을 대조한다.
9. 확정 후 10초가 넘으면 지연 경고, 15초가 넘으면 텔레그램 운영 경고를 보낸다.
10. 신호 확정 후 5분을 넘기면 신규 진입을 폐기하고 절대 추격 주문하지 않는다.

## 완전 분리

- B플랜 전용 BingX 계정과 API 환경변수만 사용한다.
- A플랜의 API 키, 계정, 포지션, 주문 테이블, 거래 기록을 사용하지 않는다.
- B플랜 API가 등록되기 전에는 주문 함수를 배포하거나 활성화하지 않는다.
- 공개 대시보드는 실행 상태만 읽고 주문 함수를 직접 호출할 수 없다.

## 반드시 남길 시간 기록

- `signal_confirmed_at`
- `dispatch_started_at`
- `exchange_accepted_at`
- `filled_at`

이 네 시각으로 신호→전송, 전송→접수, 접수→체결 지연을 각각 계산한다.
