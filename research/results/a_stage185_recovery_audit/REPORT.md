# A Stage185 실행 복구 점검 및 개선 연구

후속 상태: 로컬 수정과 행동 테스트를 완료했다. `strategy/A_RECOVERY_REPAIR_20260915.md` 및 `VERIFICATION.json` 참조. 아래는 수정 전 발견 기록이며 운영 배포 여부와 구분한다.

2026-09-15. 로컬 소스 점검과 실제 조건식 재현. 운영 DB·거래소 상태는 조회하지 않았으며 배포하지 않았다.

## 판정

직전 커밋 1c89c35는 배포 준비 완료로 간주할 수 없다. 기존 테스트 16개와 분리 감사는 통과하지만, 복구 조건의 동작 시나리오 5개 중 2개가 요구조건에 어긋났다.

1. 다음 일일 판단 이후(+25시간)에도 26시간 조건이 구 판단을 허용한다.
2. 미래 판단 시각도 경과시간 하한이 없어 허용한다.
3. 기존 orphan 신호 복구는 triggerRealTrade(signal)로 원문을 전송한다. 새 신호 생성에만 붙이는 daily_recovery 표식이 기존 신호에는 없으므로 기존 거절을 해결한다고 단정할 수 없다.
4. C 코드에서 청산 실패가 있어도 last_evaluated_closed_at을 진행시킨다. 같은 완료봉에서는 재시도되지 않으며 다음 봉에서 조건이 사라지면 실패 청산이 이어지지 않을 수 있다. 데이터 invalid 분기도 평가 완료 시각을 진행시킨다. 이는 소스 점검 발견이며 실제 장애 이력 확인은 별도로 필요하다.

## 우선 개선안

- 판단 ID·종목·방향·전략 버전·신호 ID를 DB에 함께 고정하고 원본 신호의 상태를 서버에서 재확인한다.
- 다음 정규 일일 판단 경계를 넘으면 이전 신규진입 의도를 종료한다. 단순 26시간 상수로 대체하지 않는다.
- 같은 ID의 주문 전송 여부가 불명확하면 거래소 조회로 먼저 정산한다. 반복 신호 발행으로 새 주문을 만들지 않는다.
- C 평가 완료와 C 청산 완료를 분리한다. 실패한 청산 의도를 저장하고 잔량 확인까지 재시도한다.
- 결측 데이터는 평가 성공으로 기록하지 않고 복구 후 동일 봉을 재평가한다.

## 후속 수익 연구 설계

Stage184 기준, 주문/청산 실패를 0·1·3·5분 삽입한 재생에서 기존 복구와 개선 복구를 비교한다. 미체결 수, 중복 주문 수, 무보호 시간, C 청산 지연, 추가 비용을 먼저 계산하고 전체 포트폴리오에 반영해 5년·7년 복리와 MDD를 계산한다. 이번 실행 시나리오 검증은 가격 재생이 아니므로 수익률·거래수·승률을 새로 제시하지 않는다.
